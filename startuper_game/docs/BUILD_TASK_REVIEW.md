# BUILD Task Review v3

Дата ревизии: 2026-04-10  
Источник: `godot/scripts/game_state.gd` (`_default_tasks()`, `get_weekly_tasks()`, `_default_events()`, `pick_event()`, скрипты гранта/акселератора) и `godot/scripts/main.gd` (портреты пятницы).

## Легенда пометок

- `ОК` — задача логична и полезна для Build.
- `Показать позже` — лучше показывать после набора базовой зрелости.
- `Показывать, но блокировать` — можно видеть как цель, но без эффекта до базы (превью/подсказка).
- `Дублирует другую` — смысловой дубль, лучше ротация/слияние.
- `Нужен ребаланс` — цена/эффект/частота требуют настройки.

## Ключевые правила показа (факт в текущем коде)

1. `Startup Fellows` — обязательный гейт для командных задач и командных нежданчиков (тип `Команда`).
2. `HR` — можно нанять до `Startup Fellows` (исключение).
3. Увольнения ролей показываются только если роль уже нанята.
4. `Уволить Друга` — только при `friend_count > 0`.
5. `Срочно: бридж-раунд` — `crisis_only`: в пул принудительно подмешивается при runway **менее 2,5 мес** **или** cash **ниже 30 000** (см. `_needs_emergency_funding_offer()`).
6. `Вывести продукт на рынок` — только когда выполнены условия `_can_launch_market()` (CMO, CTO, CustDev≥6, Problem≥6, MVP≥7).
7. Сборочные MVP-задачи с `omit_if_mvp_gte` скрываются при `MVP >= MVP_ASSEMBLY_TASK_HIDE_FROM` (см. константу в коде).
8. Аренда офиса B/A не показывается, если уже арендован соответствующий или более высокий класс.
9. **Грант / акселератор:** задачи только подают заявку и тратят ресурсы; **вердикт — отдельный нежданчик на следующей пятнице** (`pick_event()` → `_build_grant_verdict_event` / `_build_accelerator_verdict_event`). Кэш по гранту начисляется только из вердикта.
10. **Advisor pipeline:** флаг `has_advisor_pipeline` включают задачи «Встреча на митапе…», «Найти эксперта… письмо», принятие в программу акселератора (опции с `accelerator_accept_program`). Тогда в пуле доступны нежданчики с `requires_advisor_pipeline: true`.

## Нежданчики: как попадают в пул на Build

Маппинг этапа (`_event_matches_stage`): если у события задан `stage`, используется только он; иначе для **Build** допускаются типы **`Продукт`**, **`Команда`**, **`Техника`** (типы `Инвестор`, `Рынок`, `PR/Репутация`, `Адвайзер` без поля `stage` **не** попадают в build-пул).

Дополнительно: `pick_event()` **в первую очередь** отдаёт скриптовые вердикты, если висят `pending_grant_review` или `pending_accelerator_review` (это не элементы `event_pool`).

Фильтры мира (`_event_matches_world_state`): см. колонку «Зависимости». Неделя 1 — нежданчика нет (`should_roll_event_this_week`).

### Нежданчики, которые на Build обычно не попадают (другой тип или этап)

- Тип **`Инвестор`**, **`Рынок`**, **`PR/Репутация`** без `stage: build` — **не проходят** неявный build-фильтр (пример: «Инвестор спрашивает: где x3», «Фонд предлагает деньги», «Конкурент запустил фичу») — ожидаются на **Fit/Scale** или после релиза.
- События с **`requires_live_product`** — только после выхода на рынок.
- События с явным **`stage: fit`** / **`scale`** — не для Build.

## Иллюстрации нежданчиков и пробелы для арта

### Как сейчас устроено в коде

- У событий из `event_pool` **нет** поля `illustration` — картинка сцены не задаётся.
- В `main.gd` для экрана пятницы выбирается **портрет говорящего**: `speaker_texture` / роль / тип / скрипт (`grant_verdict` → CFO, `accelerator_verdict` → эксперт), затем текстура из словаря `_friday_role_portraits` или preload (investor, CCO SVG и т.д.).
- Если в событии **вручную** задать `illustration: "res://..."` и файл существует — **показывается полноэкранная иллюстрация** вместо портрета (`_apply_friday_intro_event_art`).

### Ассеты портретов (уже есть в `godot/assets/`)

| Ключ / назначение | Файл (основа) |
|-------------------|----------------|
| HR, CFO, COO, CMO, CTO | `portrait_hr.png`, `portrait_cfo.png`, `portrait_coo.png`, `portrait_cmo.png`, `portrait_cto.png` |
| Друзья | `portrait_friend1.png` … `portrait_friend3.png` |
| Команда / заглушка | `startup_fellows_team.png` |
| Эксперты / адвайзеры | `expert1.png`, `expert2.png` |
| Инвестор (fallback UI) | `investor` через отдельную текстуру сцены |
| CCO | `cco.svg` |
| Типы без отдельного PNG | часто **marketer** или **Команда** → см. `_event_speaker_profile` |

### Таблица: нежданчик → что рисуется сейчас

| Нежданчик (коротко) | Визуал в UI |
|---------------------|-------------|
| Вердикт гранта | Портрет **CFO** (`portrait_cfo` / cfo) |
| Вердикт акселератора | **expert1** или **expert2** по чётности недели |
| С CFO в тексте / `requires_roles: CFO` | **CFO** |
| С CTO | **CTO** |
| С CMO | **CMO** (marketer portrait) |

| Тип **Инвестор** | Текстура инвестора |
| Тип **Команда** (без роли) | `startup_fellows_team` |
| Тип **Техника** | **CTO** |
| Тип **Продукт** | **Команда** (общая) |
| Тип **Финансы** (без скрипта) | как у **Команды** (до добавления скрипта — уточнять в UI) |

**Отдельные картинки под каждый заголовок нежданчика в репозитории не требуются** — достаточно текущих аватаров.  

### Что имеет смысл дорисовать (опционально)

1. **Уникальные `illustration` по ключевым сюжетам** (грант, акселератор, офисные запросы, демо-сбой) — если нужен единый визуальный стиль «иллюстрация сцены», а не только голова спикера: завести PNG и прописать `illustration` в словаре события.
2. **Портрет CPO** — в диалогах CPO сейчас может маппиться на **CTO**-текстуру (проверьте `_event_speaker_profile`); для узнаваемости можно добавить `portrait_cpo.png` и ключ в `_friday_role_portraits`.
3. **Единый кадр для PR/Рынок** — сейчас часто используется маркетер; отдельный арт по желанию.

Итого для продакшена **обязательных** новых файлов под нежданчики **нет**; новые изображения нужны только если вы переходите на схему «одна иллюстрация = одно событие» через поле `illustration`.

## Что изменилось относительно v2

- В таблицу задач добавлены **CPO**, **CCO**, новые исследовательские и программные задачи (трендвотчинг, мероприятие, **письмо эксперту**, **грант/акселератор Build**), уточнены гейты (**юридический аудит** зависит от лендинга, аналитика — от прототипа).
